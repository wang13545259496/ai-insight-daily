# AI Insight Daily 生产环境检查清单 V1.0


## 使用目的


任何代码进入生产环境前：

必须完成本检查。



目标：

保证：

稳定发布。

快速发现问题。

降低生产风险。



================================

# 一、发布前检查


## 代码状态


确认：


□ Git状态正常。


□ 修改内容已提交。


□ 当前版本已记录。



检查：

git status



================================

# 二、依赖检查


确认：


□ package.json正常。


□ npm依赖安装成功。


□ Node版本符合要求。



检查：


node -v


npm -v



================================

# 三、构建检查


执行：


npm run build



确认：


□ 构建成功。


□ 无TypeScript错误。


□ 无严重Warning。



================================

# 四、数据库检查


确认：


□ Prisma状态正常。


□ Migration完整。


□ 数据已备份。



检查：


npx prisma migrate status



================================

# 五、服务检查


PM2检查：


pm2 status



确认：


□ ai-insight-daily运行中。


□ 无异常重启。



日志检查：


pm2 logs ai-insight-daily



================================

# 六、网站检查


检查页面：


□ 首页。


□ 新闻页面。


□ 事件页面。


□ 行业页面。


□ 投资页面。


□ Agent页面。


□ 管理后台。



确认：

页面正常加载。



================================

# 七、接口检查


检查：


API是否返回正常。


数据是否正常。


错误状态是否处理。



================================

# 八、数据检查


确认：


新增数据正常。


新闻数量正常。


重复数据没有异常增长。


AI分析任务正常。



================================

# 九、上线后观察


上线后观察：


10分钟：

检查错误日志。



1小时：

检查服务状态。



24小时：

检查数据质量。



================================

# 十、失败处理


如果上线异常：


第一：

停止继续修改。



第二：

查看日志。



第三：

定位问题。



第四：

恢复上一版本。



第五：

记录原因。



================================

# 十一、AI执行要求


AI不得：


直接修改生产环境。


跳过测试。


忽略错误日志。



AI必须：


说明修改内容。


说明测试结果。


说明上线影响。



================================

# 发布确认模板


版本：

日期：

影响模块：

上线结果：

================================

让AI成为：

可靠开发助手。


而不是：

不可控生产修改工具。
