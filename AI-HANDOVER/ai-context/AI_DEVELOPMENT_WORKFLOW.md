# AI Insight Daily AI开发协作流程 V1.0


## 目标


建立稳定的：

用户

↓

AI分析

↓

代码修改

↓

测试验证

↓

版本记录

流程。



================================

# 第一阶段：提出需求


用户提供：


功能目标。


问题描述。


期望结果。



AI不要立即写代码。



================================

# 第二阶段：AI分析


AI必须先说明：


## 1. 需求理解


当前问题是什么。


## 2. 影响范围


涉及：

页面。

组件。

API。

数据库。

AI逻辑。



## 3. 修改方案


说明：

准备修改哪些文件。


为什么这样修改。



## 4. 风险


说明：

可能影响什么。



================================

# 第三阶段：执行修改


修改原则：


优先小范围修改。


保持已有功能。


不要无意义重构。



涉及数据库：

必须说明Migration方案。



================================

# 第四阶段：测试


修改完成后：


必须执行：


构建测试：

npm run build



数据库检查：

npx prisma migrate status



服务检查：

pm2 status



================================

# 第五阶段：结果反馈


AI必须输出：


修改文件：


修改内容：


测试结果：


是否需要继续优化：



================================

# 第六阶段：提交版本


完成后：


git add


git commit


git push



提交信息规范：


feat:

新增功能。


fix:

修复问题。


refactor:

代码优化。


docs:

文档更新。



================================

# 第七阶段：同步AI知识


重大修改后更新：


CURRENT_STATUS.md


PROJECT_STATUS_SNAPSHOT.md


CHANGELOG.md


AI_DECISION_LOG.md



================================

# AI禁止行为


禁止：


不了解项目直接重构。


一次修改大量核心文件。


跳过测试。


删除历史数据。


修改数据库不说明。



================================

# 用户沟通规则


如果需求不明确：

先询问。


如果影响重大：

先确认。



如果只是小优化：

可以直接执行。



================================

# 长期目标


让AI成为：

长期技术伙伴。


而不是：

一次性代码生成工具。
