# AI Insight Daily AI测试规范 V1.0


## 测试目标


确保每次修改：

不破坏已有功能。

不污染数据。

不影响生产稳定性。



================================

# 修改分类测试


## 1. 前端页面修改


必须检查：


页面是否正常打开。


数据是否正常显示。


移动端是否适配。


控制台是否有错误。



检查页面：


首页


/news


/events


/industry


/investment


/agent



---


## 2. 后端接口修改


必须检查：


接口返回状态。


参数验证。


异常处理。


日志记录。



---


## 3. 数据库修改


必须检查：


Prisma Schema。


Migration状态。


数据兼容性。



流程：


修改schema

↓

migration

↓

测试数据库

↓

生产部署



---


## 4. AI分析逻辑修改


必须检查：


输入是否正确。


输出格式是否稳定。


是否出现：

幻觉。

无依据判断。

错误分类。



================================

# 发布前检查清单


## 代码


确认：

git状态正常。


无未提交重要修改。



---


## 构建


执行：


npm run build



要求：

成功。



---


## 数据库


检查：


npx prisma migrate status



要求：

正常。



---


## 服务


检查：


pm2 status



确认：

服务运行。



---


## 网站


访问：


首页。


新闻页。


核心功能页。



================================

# 数据质量测试


新闻新增后检查：


来源。


时间。


重复。


内容质量。


AI评分。



禁止：

未经验证大量进入数据库。



================================

# Agent测试标准


Agent必须验证：


1.

是否使用正确数据。


2.

是否引用来源。


3.

是否区分事实和推测。


4.

输出是否可行动。



================================

# 回归测试


重大修改后：


必须检查已有能力。


包括：


新闻展示。


事件聚合。


趋势分析。


投资模块。


管理后台。



================================

# 测试记录


每次重要升级记录：


版本：

日期：

修改内容：

测试结果：

问题：

解决方案：



================================

# 原则


快速开发。

严格验证。


不要：

为了速度跳过测试。
