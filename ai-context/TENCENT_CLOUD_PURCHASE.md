## 第二步：四个关键选择

### ① 地域 —— **中国香港**

页面上通常叫「**地域**」或「**可用区**」。

```
✅ 中国香港
❌ 广州 / 北京 / 上海 / 南京   （需要 ICP 备案，且采集国际源差）
❌ 新加坡 / 硅谷 / 东京        （国内访问慢，香港最好）
```

**这一项选错，整个方案就废了。**

### ② 镜像 —— **系统镜像 → Ubuntu 24.04 LTS**

```
✅ 系统镜像 → Ubuntu → Ubuntu 24.04 LTS 64bit
❌ 应用镜像（预装宝塔/WordPress 那些）
```

我们手动装环境，预装的反而碍事。

> 没有 24.04 就选 **Ubuntu 22.04 LTS**，脚本两个版本都支持。

### ③ 套餐 —— **2核2G**

| 套餐 | 够不够 | 说明 |
| --- | --- | --- |
| 1核1G | ⚠️ 勉强 | 构建时靠 2G swap 硬撑，`npm ci` + build 可能跑 10 分钟 |
| **2核2G** | ✅ **推荐** | 构建 1–2 分钟，日常 250MB 内存绰绰有余 |
| 4核4G | 过剩 | 没必要多花钱 |

我们实测：Next.js 常驻 **206MB**，cloudflared **40MB**。
2G 内存里构建时有 1–1.5GB 峰值余量。

### ④ 时长 —— **先买 1 个月**

```
✅ 1 个月（约 32 元）
❌ 直接买 1 年
```

**理由**：先用一个月验证迁移全流程能跑通。跑通之后再续年付
（年付通常有折扣，且续费价比新购价高，注意看）。

> 购买时留意「**自动续费**」开关——不需要就关掉，
> 否则到期自动扣款。

## 第四步：买完立刻做三件事

进入控制台：<https://console.cloud.tencent.com/lighthouse>

### ① 重置 root 密码

实例列表 → 找到你的实例 → **更多** → **重置密码**（或实例详情页里的「重置密码」）

设置一个强密码，**记下来**。这是后面 SSH 登录用的。

### ② 检查防火墙是否放行 22

实例详情 → **防火墙** 标签页

腾讯云轻量默认一般已放行 `22`、`80`、`443`，但**必须确认**：

| 应用类型 | 协议 | 端口 | 是否必须 |
| --- | --- | --- | --- |
| SSH | TCP | 22 | ✅ **必须** |
| HTTP | TCP | 80 | 可选（走隧道不需要） |
| HTTPS | TCP | 443 | 可选（走隧道不需要） |

**22 没放行 = 我连不上服务器 = 迁移无法进行。**

### ③ 记录公网 IP

实例列表页的「**公网 IP**」，形如 `43.xx.xx.xx`。

## 常见疑问

**Q：能不能选新加坡？**

能跑，但国内访问延迟从约 50ms 变 80–120ms。采集国际源没区别。
除非香港套餐售罄，否则选香港。

**Q：1核1G 真的不行吗？**

能跑。脚本会自动加 2G swap。代价是 `npm ci` 和 `next build`
慢 3–5 倍，每次部署要多等几分钟。首次迁移建议 2核2G，跑顺了再降配也行。

**Q：需要买流量包吗？**

不需要。我们每月实际流量约 **235MB**，套餐自带的额度（通常 1TB）
是需求的四千倍。

**Q：备案怎么办？**

香港节点**不需要** ICP 备案。这也是选香港而不是广州的原因之一。

**Q：域名怎么接？**

两种都行——

1. 直接 A 记录指向香港 IP（最快，约 50ms，需自己配 SSL 证书）
2. 保持 Cloudflare 隧道（保持现状，有防护但慢）

详见 `MIGRATION_TO_CLOUD.md` 第七节。
