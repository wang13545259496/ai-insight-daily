| --- | --- | --- |

| 趋势判断 | ✅ | 提示词要求趋势判断必须有历史对照（「与此前…路线不同」） |

## 关键交付物

**提示词改进**（`lib/ai-summary.ts`）

原问题：`impact` 字段 87% 以「对AI产业而言，…」开头，所有来源一致
（OpenAI 88%、arXiv 97%、OSChina 78%），说明是提示词造成的而非数据问题。

改法：禁止公式化开头、禁用「对X而言…对企业来说…」两段并列、
要求从具体对象切入、趋势判断必须有历史对照。

效果：实测 317 条样本，公式化比例 **79% → 0%**，
impact 平均长度 140 → 169 字。

**实体体系**（阶段 1-5 全部完成）

```
Entity        1502 个（company 542 / product 516 / model 260 / person 184）
NewsEntity    5448 条（subject 2115 / background 3333）
EventEntity    176 条（其中主体 101）
页面          /entities 与 /entities/[id]
```

实体页可看：关联事件、相关新闻（主体优先）、共同出现主体。

## 未做的部分（已确认无解或价值不足）

- **趋势的时间轴可视化**：事件只覆盖 2 天（10-14 ~ 10-15），
  画不出有意义的趋势线。需要有更多历史事件数据后再考虑。
- **父实体层级**：`Amazon ⊂ Amazon Bedrock`、`ChatGPT ⊂ ChatGPT Ads`
  等 98 组父子关系尚未用字段表达。当前靠展示层去重规避，
  未建模为层级。
- **实体类型标注错误**：抽取阶段把部分非产品标成了 product
  （`OpenAI Academy` 是项目、`Axios` 是公司）。
  属标注质量问题，未系统性修正。

# 已完成任务

## TASK-003

名称：

逐日行程地图可读性


状态：

已完成（2026-10-20）


背景：

维护者反馈「逐日行程地图标注不清楚，没有按 1/2/3/4 标注连线，
生成的图意义不大」。


做了什么：

- 缩放级别改为按当天点位跨度自动计算（原写死 13 级，跨度大的天标注全在画面外）
- 编号改为自绘大号圆点（高德 markers 的 label 只能单字符、字号极小）
- 同一坐标合并为一个编号，网页活动行与地图编号一一对应
- Word 导出改用同一张合成图
- 新增接口 /api/travel/[id]/map?day=N（鉴权 + 归属校验）


验证：

- 全量测试 511 项通过
- npm run build 通过
- next start 实测：5 天地图 200 image/png，页面 5 图 22 编号，
  Word 导出 1.68MB 内嵌 5 张 1440×810 PNG
- 未登录 401，方案/天数不存在 404


实现位置：

- lib/agents/travel/daymap-core.ts（纯计算）
- lib/agents/travel/daymap.ts（合成）
- app/api/travel/[id]/map/route.ts（接口）
- components/agent-travel/PlanView.tsx（编号圆点与图注）
