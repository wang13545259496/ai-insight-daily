# AI Insight Daily AI发布流程规范 V1.0


## 发布目标


保证：

稳定开发。

安全上线。

快速恢复。



原则：

先验证。

后发布。

可回滚。



================================

# 发布生命周期


开发

↓

代码检查

↓

测试

↓

提交

↓

备份

↓

部署

↓

验证

↓

记录



================================

# Stage 1 开发阶段


要求：


修改前：

阅读：

PROJECT_MEMORY.md


确认：

是否符合项目方向。



修改时：

记录：

修改文件。

修改原因。

影响范围。



================================

# Stage 2 本地验证


必须执行：


代码检查。


功能测试。


数据库检查。



最低要求：


npm run build



确认：

构建成功。



================================

# Stage 3 Git提交


提交信息格式：


类型:

描述



例如：


feat: add agent analysis module


fix: repair news quality filter



禁止：

无意义提交信息。



================================

# Stage 4 发布前备份


确认：


当前版本。


数据库状态。


环境变量。



记录：


Git commit。


发布时间。



================================

# Stage 5 生产部署


标准流程：


拉取代码。


安装依赖。


执行migration。


重新构建。


重启服务。



例如：


git pull


npm install


npx prisma migrate deploy


npm run build


pm2 restart ai-insight-daily



================================

# Stage 6 上线验证


检查：


首页。


新闻。


事件。


后台。


API。



确认：

无错误日志。



================================

# 回滚流程


如果出现问题：


第一步：

停止继续修改。



第二步：

查看错误日志。



第三步：

恢复上一版本。



方式：


git checkout <commit>



第四步：

重新构建。



第五步：

恢复服务。



================================

# AI发布权限


AI可以：


生成修改方案。


修改开发代码。


生成测试方案。



AI必须确认：


生产部署。


数据库变更。


删除操作。
